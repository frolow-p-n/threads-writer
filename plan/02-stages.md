# 02. Стадии 0–7

## Стадия 0. Подготовка (1 день)
- Meta-приложение с продуктом Threads API, свой аккаунт добавить тестером (App Review для своего аккаунта не нужен).
- Права: `threads_basic`, `threads_content_publish`, `threads_manage_replies`, `threads_read_replies` (+ `threads_manage_insights` для аналитики).
- Долгоживущий токен (60 дней) + автоматический refresh.
- Ключ OpenAI, месячный лимит расходов (~$5).

## Стадия 1. Персона и характер (1–2 дня)
- `persona.md`: биография, манера речи, сленг, темы, табу, 5–10 эталонных постов, правила.
- `memory`: последние 30–50 постов и использованные сюжеты.

## Стадия 2. Текстовые посты (2 дня)
- Writer: персона + тема/настроение + память -> пост до 500 символов.
- Банк тем/рубрик для разнообразия. Structured output JSON.

## Стадия 3. Фото-пайплайн (2–3 дня)
- Случайное неиспользованное фото, отметка в БД.
- Vision-описание (кэшируется), `detail: low`.
- Жанры: фантастика, юмор, хоррор, детектив, сказка, ностальгия; взвешенный выбор, не повторять подряд.
- Фото нужно залить в публичное хранилище (Cloudinary / R2 / Supabase Storage), сжать до ~1–2 МП. Скрипт `upload-photos`.

## Стадия 4. Критик (2 дня)
Рубрика: соответствие персоне; связь с фото (нет выдуманных деталей, которых нет в описании); длина и повторы; безопасность (оскорбления, политика, личные данные, мед. советы); ИИ-штампы.
Логика: score >= 7 публикуем; иначе Writer переписывает по замечаниям (макс. 2 раза); не прошло — отбросить и залогировать. Критик лучше на другой модели, чем Writer.

## Стадия 5. Тестовый режим (1–2 дня)
- `--dry-run` генерирует N постов -> `out/review.md` (текст, фото, жанр, оценка, причины правок).
- Опционально Telegram-бот с кнопками «Одобрить/Отклонить» (`approval_mode`) на первые 1–2 недели.
- Здесь подбираются промпты и порог критика.

## Стадия 6. Публикация и расписание (2 дня)
- Двухшаговая публикация Threads API.
- Случайное время внутри окон (jitter), ретраи, идемпотентность (не публиковать дважды), аварийный стоп-флаг.

## Стадия 7. Ответы на комментарии (2–3 дня)
- Опрос новых ответов каждые 15–30 мин.
- Классификатор (nano): `emoji_only` / `short_text` / `ignore` / `escalate`.
- Ответ через критика; лимит ответов в час; не отвечать на оскорбления; текст комментария в промпте как данные (защита от prompt injection).
- Первые недели ответы тоже через одобрение.

**Оценка:** MVP с dry-run (стадии 0–5) ~1–1.5 недели; полная версия ~3 недели.
