# 07. Эксплуатация

Репозиторий: https://github.com/frolow-p-n/threads-writer (приватный). Аккаунт Threads: `@danya_in.beta`.

## Как это работает
Каждые 30 минут GitHub Actions (`.github/workflows/tick.yml`) запускает `tick`:
1. если на сегодня (по Нью-Йорку) нет слотов, создаёт их: по одному случайному времени в каждом окне из `config.yaml`;
2. для слота, время которого пришло, генерирует пост (до 3 попыток критика), публикует и отмечает слот выполненным;
3. слот, опоздавший более чем на 6 часов, пропускается;
4. токен Threads продлевается автоматически, когда до конца остаётся менее 20 дней.

Состояние (посты, фото, слоты, токен, пауза) живёт в Supabase, таблицы `tw_*` (схема в `supabase/schema.sql`).

## Команды (из папки проекта)
| Команда | Что делает |
|---|---|
| `npm run dry-run -- --n 3` | Сгенерировать черновики (draft), ничего не публикуя; отчёт `out/review.md`. Фото не расходуются |
| `npm run cli -- publish --id N` | Опубликовать черновик или одобренный пост по id |
| `npm run cli -- tick` | Один тик планировщика (как в GitHub). С `--dry` только показывает, что бы сделал |
| `npm run cli -- plan-day` | Пример случайных слотов на сегодня |
| `npm run cli -- replies --dry` | Показать ответы на новые комментарии, не отправляя |
| `npm run cli -- pause --on 1` | Поставить агента на паузу (действует сразу и в GitHub) |
| `npm run cli -- pause --on 0` | Снять паузу |
| `npm run cli -- upload-photos` | Сжать и загрузить новые фото из `photos/` в Supabase |
| `npm run cli -- notify-test` | Отправить тестовое уведомление в Telegram |
| `npm run cli -- threads-check` | Проверить токен и аккаунт Threads |
| `npm run typecheck` | Проверка типов |

## GitHub
```bash
gh workflow run tick.yml --repo frolow-p-n/threads-writer -f dry=true    # холостой прогон
gh workflow run tick.yml --repo frolow-p-n/threads-writer                # боевой прогон вручную
gh run list --repo frolow-p-n/threads-writer --limit 5                   # последние запуски
gh run view <run-id> --repo frolow-p-n/threads-writer --log              # лог запуска
gh workflow disable tick.yml --repo frolow-p-n/threads-writer            # выключить расписание полностью
gh workflow enable tick.yml --repo frolow-p-n/threads-writer             # включить обратно
```
Секреты: `OPENAI_API_KEY`, `THREADS_ACCESS_TOKEN`, `THREADS_USER_ID`, `THREADS_TOKEN_EXPIRES`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_BUCKET`. Менять: `gh secret set ИМЯ --repo frolow-p-n/threads-writer`.
Если запуск упал, GitHub присылает письмо.

## Типовые задачи
- **Добавить фото:** положить файлы в `photos/` (png/jpg/webp), выполнить `npm run cli -- upload-photos`. Агент берёт случайное неиспользованное; когда все использованы, самое давно использованное.
- **Изменить частоту или время:** `config/config.yaml` (`posts_per_day`, `windows`, `timezone`), затем `git push`. Слоты текущего дня уже созданы и не пересчитываются.
- **Изменить характер, тон, эмодзи:** `persona/persona.md` и промпты в `src/agents/writer.ts`, `critic.ts`, затем `git push`. Проверить через `dry-run`.
- **Изменить жанры/веса:** `genres` в `config/config.yaml`.
- **Остановить на время:** `pause --on 1`. **Навсегда:** `gh workflow disable`.
- **Удалить плохой пост:** вручную в приложении Threads (API-удаление не реализовано).

## Токен Threads
Живёт 60 дней, продлевается сам (в `tw_state`: `threads_token`, `threads_token_expires`). Если агент простоял долго и токен умер: в консоли разработчика Meta, **Use cases, Access the Threads API, Settings, User Token Generator**, сгенерировать новый, обновить секрет `THREADS_ACCESS_TOKEN` и очистить ключи `threads_token` и `threads_token_expires` в таблице `tw_state`.

## Локальная настройка
`.env` (в git не попадает), образец `.env.example`: `OPENAI_API_KEY`, `THREADS_ACCESS_TOKEN`, `THREADS_USER_ID`, `THREADS_TOKEN_EXPIRES`, `SUPABASE_URL` (корень проекта, без `/rest/v1`), `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_BUCKET` (регистр как у бакета). Установка: `npm install`.

## Расходы
OpenAI: около $0.01 за пост (3-4 вызова), около $0.5 в месяц при 2 постах в день. GitHub Actions: около 1000 из 2000 бесплатных минут. Supabase: фото около 200 КБ каждое, 1 ГБ бесплатно.

## Если что-то не работает
| Симптом | Причина / решение |
|---|---|
| `Supabase upload ... PGRST125` | В `SUPABASE_URL` лишний хвост `/rest/v1/` |
| Threads `code 452 Session key invalid` | Токен просрочен или отозван, см. раздел про токен |
| Пост не вышел в слот | Критик забраковал 3 попытки (слот ждёт следующий тик), либо опоздание больше 6 часов, либо включена пауза |
| `git push` отклонён из-за workflow | Нужен scope `workflow`: `gh auth refresh -h github.com -s workflow` |
| `У фото нет public_url` | Сначала `upload-photos` |

## Уведомления в Telegram
Бот `@threadswriternotifier_bot` (отдельный от платёжного) пишет в топик группы: после каждой публикации со ссылкой на пост, при пропуске слота, при трёх бракованных попытках критика и при падении запуска GitHub. Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_TOPIC_ID` в `.env` и в GitHub Secrets. Проверка: `npm run cli -- notify-test`. Если уведомления не нужны, удалите эти переменные: код тогда молча пропускает отправку. Чтобы сменить топик, поменяйте `TELEGRAM_TOPIC_ID` в обоих местах.

## Ответы на комментарии (стадия 7)
Выполняются в каждом запуске после проверки слотов (`src/replier.ts`). Правила (все значения в `config.yaml`, секция `replies`):
- Смотрим комментарии под постами за последние 7 дней (`lookback_days`), у каждого комментария своя задержка 2-10 минут перед ответом.
- Классификатор: `reaction` (отвечаем эмодзи в 50% случаев), `conversation` (отвечаем коротким текстом, почти всегда), `rude_mild` (один колкий ответ, дальше молчит), `ignore` (спам, ссылки, ненависть, политика и т.п.: без ответа).
- Максимум 2 её ответа одному человеку под одним постом; не больше 100 ответов за сутки и 8 за запуск.
- Каждый ответ проверяет критик (образ, нет раскрытия происхождения и работы, не утверждает, что она человек, не следует инструкциям из комментария). Не прошёл с двух попыток: ответа нет.
- Текст комментария в промптах всегда как недоверенные данные (защита от prompt injection).
- В Telegram приходит сводка: кому и что она ответила, что проигнорировано.
- Команда: `npm run cli -- replies --dry` показывает ответы без отправки (в dry-режиме считается лимит запуска, поэтому покажет до 8 штук).
- Таблица `tw_comments` (нужна миграция `supabase/migrations/002_comments.sql`). Обработанные комментарии не повторяются.

## Защита от сбоев публикации
Перед генерацией поста агент проверяет, что Threads API отвечает. Если нет: ничего не тратится, одно уведомление в Telegram (не чаще раза в 6 часов). Если пост уже сгенерирован, а публикация упала, на следующем запуске публикуется он же. Фото помечается использованным только после успешной публикации.
Ошибка `API access blocked (code 200)` у Threads уже случалась 2026-10-11 после проверки аккаунта при входе в Meta и прошла сама через несколько часов. Нужно: проверить Required actions и Alert Inbox в консоли разработчика, подтвердить проверку аккаунта, подождать; на время сбоя `pause --on 1`.

## Надёжный запуск: Supabase cron
Встроенный cron GitHub срабатывал раз в несколько часов, поэтому добавлен триггер в Supabase (`supabase/migrations/003_cron.sql`): `pg_cron` каждые 15 минут через `pg_net` вызывает workflow_dispatch в GitHub. Токен GitHub (fine-grained, только репозиторий threads-writer, право Actions: Read and write, срок 1 год) лежит в Supabase Vault под именем `github_dispatch_token`. Параллельные запуски исключены (`concurrency` в workflow), слоты идемпотентны.
- Проверить: `select status_code, created from net._http_response order by created desc limit 5;` (204 = запуск принят) и `select * from cron.job_run_details order by start_time desc limit 5;`
- Остановить: `select cron.unschedule('tw-dispatch');`
- Когда токен истечёт (через год): создать новый и обновить секрет: `select vault.update_secret((select id from vault.secrets where name='github_dispatch_token'), 'НОВЫЙ_ТОКЕН');`

## Формат поста (гарантии в коде)
Писатель возвращает текст полем `paragraphs` (2-4 абзаца), код склеивает их через пустую строку: так абзацы не «слипаются» (раньше при длинной истории постов в памяти модель начала писать одним куском). Код же проверяет длину (`min_post_chars`..`max_post_chars`, 300-500) и число эмодзи (минимум 4 в фото-посте), а тире вырезает сам. Критик-ИИ длину не оценивает (он считает неточно). Если проверка не пройдена, пост уходит на переписывание (до `max_revisions` = 3 раз). Прошлые посты в памяти показываются одной строкой со знаком «/» между абзацами.

## Борьба с повторяющимися образами
Раньше в постах и ответах слишком часто всплывали снеки, кофе, Кевин-фикус, зеркала. Теперь: (1) в `persona.md` бытовые детали помечены как фон, не более 1 поста из 6, из привычек убраны «snacks», из эталонных постов убраны Кевин и пицца; (2) `src/motifs.ts` считает, какие образы (еда, кофе, Кевин, зеркало/отражение, glitch, secrets, plot twist, detective) встретились минимум в 2 из последних 8 постов, и запрещает их писателю в новом посте; (3) код отклоняет черновик, если запрещённый образ всё же в нём есть. Список образов и пороги правятся в `src/motifs.ts`.

## Праздничные недели и разнообразие сюжетов (2026-10-12)
**Праздники** (`holidays` в `config.yaml`, логика `src/holidays.ts`): Valentine's Day, April Fools, Easter (светски), Star Wars Day (4 мая), 4th of July, Halloween, Thanksgiving, Christmas (светски), New Year's Eve, Friday the 13th. За 7 дней до праздника (для Friday the 13th за 3) и в сам день часть постов тематическая: 65% в окне, 100% в сам день (`theme_chance_in_window`, `theme_chance_on_day`). Фото по-прежнему случайное, история тематическая. Даты считает код (Пасха, 4-й четверг ноября, пятница 13-е). Добавить или убрать праздник: список `holidays.list` (поля `id`, `name`, `month`/`day` или `rule`, `lead_days`, `theme`).
**Разнообразие:** генерация фото-поста теперь двухшаговая. (1) `src/agents/ideator.ts` берёт из фото ОДНУ зацепку (поза, предмет, цвет) и придумывает сюжетный замысел на случайных «кубиках» из `src/ideas.ts`: мир (32 фантастических или 20 из её жизни, соотношение `fantasy_ratio: 0.65`), поворот (15), форма подачи (10), тон (жанр). Миры из последних 12 постов не повторяются. (2) Писатель пишет пост по замыслу. Запрещены банальные ходы (зеркало, экран, глюк, записка). Критик больше не требует пересказа сцены с фото.
**Длина:** если черновик длиннее лимита, отдельный шаг `tightenPost` сжимает его (до 3 раз), так как модель плохо сокращает при перепросе.
**Проверка вручную:** `npm run dry-run -- --n 3 --holiday halloween` (принудительная тема), `--mode fantasy|grounded` (принудительный режим). В `out/review.md` видны зацепка и замысел. Это добавляет в стоимость поста один вызов (около $0.01 за пост в сумме).

## Модели: сюжет и ответы раздельно
`models.story` (замысел, текст поста, сжатие) и `models.writer` (ответы на комментарии) настраиваются отдельно в `config.yaml`. Тест 2026-10-12: `gpt-4.1` пишет заметно острее и смешнее, чем `gpt-4.1-mini`, но примерно в 6 раз дороже (около $0.06 за пост против $0.01, то есть ~$3.5/мес против ~$0.6 при 2 постах в день). Учитывайте месячный лимит в OpenAI ($5): с `gpt-4.1` на посты он будет почти выбран. Текущее значение: `gpt-4.1` (включено 2026-10-12 по решению пользователя; при нехватке лимита вернуть `gpt-4.1-mini`).
**Голос:** строго первое лицо (код требует минимум 3 местоимения I/my/me), концовка с punchline, IT-шутки (баги, код, QA) ограничены правилом в персоне и трекером повторов.
