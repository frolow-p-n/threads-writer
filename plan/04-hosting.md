# 04. Бесплатный хостинг

Агент работает по расписанию, постоянный сервер не нужен — нужен надёжный cron.

| Вариант | Для чего | Ограничения |
|---|---|---|
| **GitHub Actions** (cron) | Лучший планировщик: тики каждые 15–30 мин | Публичный репо без лимита, приватный 2000 мин/мес; cron может опаздывать на минуты |
| **Cloudflare Workers + Cron Triggers** | Лёгкий планировщик на TS, R2 для фото (10 ГБ бесплатно) | Лимит CPU на free-тарифе |
| **Supabase** (free) | Postgres, Storage, Edge Functions, `pg_cron` | Проект засыпает после недели неактивности |
| **Vercel Hobby** | Дашборд/админка, API-роуты | Cron только раз в сутки, некоммерческое использование; как основной планировщик не подходит |
| **cron-job.org** | Внешний триггер для Vercel/CF-эндпоинта (до 1/мин) | Сторонняя зависимость |
| **Neon / Turso** | Бесплатная БД | Лимиты по объёму, для задачи хватает |
| **Oracle Cloud Always Free** | VM 24/7 | Сложная регистрация, не всегда есть ресурсы |
| Render / Koyeb free | Веб-сервис | Засыпает без трафика, cron платный |

## Рекомендуемая связка
GitHub Actions (cron + запуск агента) + Supabase (БД и хранилище фото) или Neon + Cloudinary. Vercel только если нужна веб-панель настроек.

## Фото
Агент не читает локальную папку на хосте. Разовая загрузка в Supabase Storage / R2 скриптом `upload-photos`, запись в таблицу `photos`.

## Cron-задания
- каждые 15–30 мин: scheduler (публикация) + replier (комментарии)
- ежедневно: collector метрик, refresh токена (за 7 дней до истечения)
- еженедельно: analyst

## Принятое решение (2026-10-11)
GitHub Actions (приватный репозиторий, cron каждые 30 мин, около 1000 мин/мес из 2000) + Supabase (таблицы `tw_*` и публичный бакет фото). Vercel не взят: бесплатный cron раз в сутки и жёсткий лимит времени функции. Может пригодиться позже для веб-панели.
