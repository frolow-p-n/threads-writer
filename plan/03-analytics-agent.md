# 03. Агент-аналитик (стадии 8–10)

Не пишет и не публикует. Раз в неделю анализирует статистику прошлых постов и предлагает успешные направления; результат — мягкие подсказки для Writer и Scheduler. Персону не меняет.

```
Threads Insights API -> Collector -> БД (метрики)
                                       v
                       Analyst (код считает, LLM интерпретирует)
                                       v
              insights.md + веса жанров/тем -> Writer/Scheduler
                                       v
              отчёт в Telegram (+ одобрение рекомендаций)
```

## Стадия 8. Collector (1 день)
- Раз в сутки собирает метрики постов старше 24 ч; повторно через 3 и 7 дней.
- Метрики поста: views, likes, replies, reposts, quotes, shares. Аккаунт: followers_count и динамика.
- Права: `threads_manage_insights`.
- Метаданные нашей генерации (жанр, тема, тип, длина, время/день недели, оценка критика, эмодзи/вопрос в конце) пишутся в БД с первого дня.

## Стадия 9. Analyst (2–3 дня)
Расчёт кодом (не LLM):
- score поста, например `(likes + 3*replies + 3*reposts + 2*quotes) / views`.
- Агрегаты по жанру, теме, фото/текст, длине, часу, дню недели.
- Рекомендация только при группе >= 8–10 постов, иначе «мало данных». Сравнение с медианой аккаунта. Выбросы и первые 2 недели исключаются.

LLM (раз в неделю, gpt-4.1-mini / gpt-5-mini) получает агрегаты + топ-5 и худшие 5 постов, возвращает JSON:
```json
{
  "winning": [{"dimension":"genre","value":"...","evidence":"..."}],
  "losing": [],
  "hypotheses": [],
  "experiments": [{"what":"...","why":"..."}],
  "schedule_tips": [],
  "confidence": "low|medium|high"
}
```
Отчёт в Telegram + `insights.md` с историей выводов.

## Стадия 10. Применение рекомендаций
- Bandit: 70–80% exploit (выигрышные направления), 20–30% explore.
- Веса меняются плавно (не более ±20% за неделю), никогда не до нуля.
- Противоречие `persona.md`/табу -> рекомендация отклоняется.
- Сначала изменения весов только через одобрение в Telegram, позже автоприменение.
- В промпт Writer добавляется короткий блок «что хорошо заходило» (2–3 строки), не вся статистика.

## Прочее
- Хостинг: два дополнительных cron-задания в GitHub Actions (ежедневное, еженедельное).
- Делать после 2–3 недель публикаций, иначе данных нет.
- Риски: малая выборка (шум), дрейф к кликбейту (вердикт критика приоритетнее), задержка метрик (смотреть посты 24 ч+).
